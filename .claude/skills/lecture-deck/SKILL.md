# 강의 덱 만들기

이 스킬로 만드는 덱은 PPT가 아니라 **키보드로 넘기는 발표용 HTML 파일 하나**다. 덱과 프롬프터(진행 대본)가 한 세트다.

## 순서를 지킨다

덱을 바로 쓰지 않는다. 아래 순서를 건너뛰면 다시 만들게 된다.

1. **구조 설계서** (`슬라이드구조설계.md`) — 장수·유형 배분·시간대·설계 원칙
2. 사용자 확인
3. **덱** (`deck.html`) — `assets/`의 deck.css·deck.js를 파일 안에 넣는다
4. **프롬프터** (`script.html` 또는 `script.md`) — 덱 확정 후

강사는 사람 앞에서 말로 재현해야 한다. 설계서를 먼저 보여주고 흐름에 동의를 받은 뒤에 덱을 쓴다.

## 재료는 사용자 자료만

- 사용자가 준 강의자료·녹음 받아쓴 글·자주 받는 질문·대화 내용으로만 쓴다
- 자료에 없는 숫자·후기·성과·사례는 만들지 않는다. 필요하면 "아직 없는 것"에 적고 사용자에게 묻는다
- 추측이면 추측이라고 표시한다

## 구조 설계서에 반드시 넣을 것

`templates/구조설계서.md`를 복사해 채운다. 빠지면 안 되는 것:

- **유형별 장수와 비중** — A 임팩트 문장 / B 개념 대비 / C 실제 화면·시연 표지판 / D 프로세스 / 챕터
- **시간대별 슬라이드 배분** — 몇 분에 몇 번 슬라이드인지
- **설계 원칙** — 왜 이 비중인지를 문장으로. 예: "라이브 시연을 안 하므로 캡처가 시연을 대신한다"
- **아직 없는 것** — 찍어야 할 캡처, 받아야 할 자료

라이브 시연을 하면 C 비중이 낮고 A가 높다. 시연을 안 하면 C를 절반까지 올리고 캡처를 여러 장 연속으로 보여준다.

## 덱 마크업 규칙

`assets/deck.css` 첫 줄에 적힌 규칙이다. 어기지 않는다.

- **박스·카드·패널 금지.** 테두리 친 상자에 내용을 담지 않는다
- **글자 크기 3단**만 쓴다 — `--d`(큰 제목) `--l`(보조 문장) `--m`(작은 라벨)
- **장당 강조 한 곳.** `.acc`를 한 슬라이드에 두 번 쓰지 않는다
- **성공색(`--seal`)은 마지막 장 1회**
- **움직임은 발표자가 넘길 때만.** 계속 움직이는 애니메이션 금지

색은 `:root`에서 바꾼다. 기본값: 배경 `#F7F4EC`(아이보리) · 글자 `#131313` · 강조 `#0047AB`(코발트). 사용자가 자기 색을 주면 이 세 값만 바꾼다.

쓸 수 있는 것:

```html
<section>
  <div class="kicker">상단 작은 라벨</div>
  <h1>큰 문장<br>줄바꿈은 직접 통제</h1>
  <p class="lead">
    <span class="s">한 줄</span>
    <span class="s"><span class="acc">강조는 여기 한 곳만</span></span>
  </p>
</section>

<section class="chapter"><div class="kicker">1부</div><h1>부 제목</h1></section>

<section>
  <ul>
    <li>항목<small>보조 설명</small></li>
  </ul>
</section>

<section>
  <ol class="q"><li>오늘의 지도 항목</li></ol>
  <p class="note">각주</p>
</section>
```

## 문장 쓰는 법

사용자 말투를 따른다. 따로 말이 없으면 짧은 단문, 존댓말, 과장 없음.

- 한 장에 한 메시지. 장표가 설명을 다 해버리면 강사가 할 말이 없어진다
- 질문을 던지는 장표를 쓴다 — "진짜 되는가", "어디까지 되는가"
- 결과를 먼저 보여주고 시작한다. 설명부터 하면 초반에 집중이 끊긴다
- 숫자는 사용자 자료에 있는 값만
- 이모지 쓰지 않는다

## 라이브 시연이 있을 때

시연 앞뒤에 표지판 슬라이드를 둔다. 화면을 옮겨 다니면 청중이 "지금 어디인지"를 잃는다.

```html
<section class="demo">
  <div class="kicker">지금부터 볼 것</div>
  <h1>무엇을 보는지</h1>
  <p class="lead">화면을 넘기겠습니다. 어떻게 보시면 되는지 한 줄.</p>
</section>
```

돌아와서는 "방금 본 것"을 한 문장으로 정리한다. 이 두 장 사이는 나중에 녹화본으로 바꿔 끼워도 흐름이 유지된다.

AI 작업 대기가 긴 시연은 **실행을 먼저 걸어두고** 도는 동안 설명 슬라이드를 진행한 뒤 결과를 확인하는 순서로 짠다.

## 만드는 방법

`assets/deck.css`와 `deck.js`를 읽어 `<style>`·`<script>` 안에 그대로 넣고, 슬라이드를 이어 붙여 `deck.html` 하나로 만든다. 파일 하나면 어디서든 열린다. 글꼴은 아래 CDN 한 줄을 `<head>`에 넣는다.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard.min.css">
```

본문 골격:

```
<div id="bar"></div>
<div id="stage"> ...섹션들... </div>
<div id="hud"><span id="cur">1</span> / <span id="tot">0</span></div>
```

`deck.js`가 `cur`·`tot`·`bar`를 참조하므로 이 세 요소는 빠뜨리지 않는다. 좌우 방향키·스페이스·클릭으로 넘어가고 주소 끝(#번호)에 현재 장이 남는다.

바로 쓸 수 있는 예시 파일: 키트의 `01-강의만들기/4-장표/예시-덱.html`

## 검증

만들고 끝내지 않는다.

- 브라우저로 열어 처음부터 끝까지 넘겨본다
- 슬라이드 수가 설계서와 맞는지, 이미지가 깨지지 않았는지, 강조가 두 곳인 장이 없는지 확인한다
- 브라우저를 직접 다룰 수 없는 환경이면 사용자에게 파일을 열어 넘겨봐 달라고 요청하고, 확인할 항목을 알려준다

## 프롬프터

덱이 확정된 뒤에 만든다. HTML로 만들면 `assets/script.css`를 쓴다. 들어갈 것:

- 부마다 시작 시각과 제목
- **[말]** 그대로 읽어도 되는 문장
- **[지금 하기]** 손으로 할 것 (화면 전환, 시연 창 열기)
- **[막히면]** 시연이 안 되거나 질문이 나왔을 때 할 말과 대체 방법
- 시작 전 준비물 체크리스트 — 열어 둘 것, 닫아 둘 것 (알림, 개인 대화 창)

대본량이 부족하면 현장에서 막힌다. 장표마다 동작과 멘트를 구체적으로 쓴다. 템플릿: `01-강의만들기/5-프롬프터/템플릿.md`
