# 3단계 · 구조 설계서

**하는 일** 바로 장표를 만들지 않고 뼈대 문서 한 장부터 씁니다. 몇 장인지, 몇 분에 어디까지 가는지, 왜 이 순서인지. 설계서에서 고치는 게 장표에서 고치는 것보다 훨씬 쉽습니다.

**준비할 것**

- 강의 제목
- 강의 시간
- 수강생이 강의 후 할 수 있게 되는 것 한 줄

**이 폴더의 파일**

- `템플릿.md` — 빈 설계서. 복사해서 채웁니다
- `예시-구조설계서.md` — 채운 모습 예시 (형식만 참고하세요)

## 복사할 프롬프트 · 구조 설계서 만들기

```text
지금까지 대화한 내용으로 강의 구조 설계서를 만들어 주세요. 아직 장표는 만들지 마세요.

강의 정보
- 제목: [강의 제목]
- 시간: [예) 120분]
- 수강생: [누구]
- 강의가 끝나면 수강생이 할 수 있게 되는 것: [한 줄]

설계서에 넣을 것
1. 전체 흐름: 부(파트)별 제목과 각 부의 핵심 메시지 한 줄
2. 시간표: 몇 분에 어디까지 가는지
3. 장표 목록: 번호 / 화면에 보일 문장 / 말할 내용 한 줄
4. 설계 원칙: 왜 이 순서인지 문장으로
5. 아직 없는 것: 제가 준비해야 할 자료나 화면 캡처

한 장에는 메시지 하나만 둡니다. 1·2·3·5번은 표로, 4번은 문장으로 정리해 주세요.
```

## 장표 유형 다섯 가지 (설계서에 비중을 적습니다)

| 유형 | 쓰임 |
|---|---|
| A 임팩트 문장 | 질문 던지기, 전환, "방금 본 것" 정리 |
| B 개념 대비 | 한 번에 vs 단계로, 전 vs 후 |
| C 실제 화면·시연 표지판 | 캡처, "지금부터 볼 것" |
| D 프로세스 | 순서, 지도 |
| 챕터 | 부 전환 |

라이브 시연을 하면 C 비중을 낮추고 A를 높입니다. 시연을 안 하면 C를 절반까지 올리고 캡처를 여러 장 이어 보여줍니다.

## 마음에 안 들면 이렇게 말하세요

- "2부가 너무 길어요. 전체 시간은 그대로 두고 2부를 [20]분으로 줄여 주세요."
- "결과를 먼저 보여주고 시작하도록 순서를 바꿔 주세요."

## AI 도구(Claude Code·Codex)가 진행할 때

1. `템플릿.md`를 `내작업/슬라이드구조설계.md`로 복사해 채운다.
2. 1·2단계 대화와 사용자 자료에 있는 내용만 쓴다. 비어 있는 것은 "아직 없는 것"에 적는다.
3. 설계서를 보여주고 **사용자 확인을 받기 전에는 4단계로 넘어가지 않는다.**
